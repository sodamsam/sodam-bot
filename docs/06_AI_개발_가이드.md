# ⑥ AI 개발 가이드

이 문서는 Claude 같은 AI에게 이 저장소의 문제 해결이나 기능 추가를 맡길 때,
`docs/04_기능_목록.md`와 함께 보여주면 맥락을 빠르게 파악시킬 수 있도록 정리한 문서입니다.

## 계정 컨셉

- 계정: "소담쌤의 AI 쉬운가이드" (@sodam_ai_lab)
- 타겟: 4050세대 (AI가 낯선 직장인·소상공인·부업 준비생)
- 목표: 전자책 판매 → 이후 강의 판매로 이어가는 퍼널. 팔로워 신뢰 구축이 핵심이라
  콘텐츠는 항상 진솔하고 구체적이어야 함 (과장·어그로·질문형 마무리 지양)

## 파일 구성

| 파일 | 역할 |
|---|---|
| `comment_bot.py` | 댓글 감시 → 노션 자료 매칭 → 자동 대댓글 (10분 주기) |
| `auto_post.py` | 아침/저녁 자동 글 발행 (하루 2회) |
| `post_thread.py` | 수동 글 발행 스크립트 |
| `refresh_token.py` | Threads 장기 토큰 갱신 |
| `threads_api.py` | Threads 공식 API 래퍼 (컨테이너 생성 → 대기 → 발행) |
| `notion_api.py` | 노션 API 래퍼 (자료 DB, 저녁 소재 노트 DB) |
| `config.py` | 환경변수 로더 (GitHub Secrets → os.environ) |
| `.github/workflows/*.yml` | GitHub Actions 워크플로 (댓글봇, 수동발행, 자동발행) |

## 자동 발행 흐름 (`auto_post.py`)

1. GitHub Actions가 아침 7시대/저녁 19시대 동안 20분마다 실행
2. `current_window()`로 지금이 morning/evening 범위인지 판정
3. `should_post_now()`로 오늘 그 시간대에 아직 발행 안 했는지 확인
   - **아침/저녁 모두 동일한 방식**: 범위 안이고 미발행이면 즉시 발행 (v1.6부터).
     예전에는 날짜별 랜덤 목표 시각을 기다렸다가 발행하는 방식이었는데,
     이 방식이 저녁에만 남아있던 버그를 아침과 동일한 "범위 진입 즉시 발행"으로 통일해 제거함.
4. 아침(`morning`): 사건 중심 뉴스(`NEWS_QUERIES`)를 수집해 "밤사이 AI 소식" 코너로 작성
5. 저녁(`evening`): 노션 "저녁 소재 노트" DB에서 미사용 메모를 먼저 확인
   - 있으면 → 그 메모를 뼈대로 "AI로 이렇게 바뀌었어요" 코너 작성, 발행 성공 시 메모를 "사용"으로 갱신
   - 없으면 → 기존처럼 뉴스 기반 "저녁 실전 활용팁"으로 대체 발행
6. Gemini 무료 API로 글 작성 → 줄바꿈/분량 후처리(`wrap_lines`, `trim_paragraphs`) → Threads 발행
7. 발행 기록을 `state/posted.json`에 저장 (같은 시간대 중복 발행 방지)

## 노션 DB 구조

### 1) 자료 DB (`NOTION_DATABASE_ID`) — 댓글 자동 응답용

| 속성 | 타입 | 설명 |
|---|---|---|
| 제목 (title) | 제목 | 자료 이름 |
| 키워드 | 텍스트/선택 | 댓글에 이 키워드가 있으면 이 자료 링크를 보냄 (비워두면 최신 자료 후보로만 사용) |

### 2) 저녁 소재 노트 DB (`NOTION_EVENING_DB_ID`) — 저녁 코너 반자동 발행용

DB ID: `3af246dcc32680efb00ed1bc2b8ba2fb`

| 속성 | 타입 | 설명 |
|---|---|---|
| 이름 | 제목 | 소재 제목 |
| 날짜 | 날짜 | 그 일이 있었던 날짜 (오래된 것부터 우선 사용) |
| 상황 | 텍스트 | 그날 있었던 구체적인 상황 |
| ai활용 | 텍스트 | AI로 무엇을 했는지 |
| 변화/결과 | 텍스트 | 실제로 달라진 점 |
| 사용여부 | 선택 (미사용 / 사용) | 발행에 쓰이면 봇이 자동으로 "사용"으로 갱신 |

`notion_api.get_unused_evening_note()`가 사용여부=미사용 중 날짜가 가장 오래된 1건을 가져오고,
`notion_api.mark_evening_note_used(page_id)`가 발행 성공 후 "사용"으로 갱신한다.
미사용 메모가 바닥나면 자동으로 뉴스 기반 발행으로 전환되므로, 소재 노트는 주기적으로 채워둬야 한다.

## 환경변수 (GitHub Secrets)

| 이름 | 필수 | 설명 |
|---|---|---|
| `THREADS_ACCESS_TOKEN` | 필수 | Threads 장기 토큰 |
| `NOTION_TOKEN` | 필수 | 노션 통합 시크릿 |
| `NOTION_DATABASE_ID` | 필수 | 자료 DB ID |
| `NOTION_EVENING_DB_ID` | 선택 | 저녁 소재 노트 DB ID (비워두면 `3af246dcc32680efb00ed1bc2b8ba2fb` 기본값 사용) |
| `GEMINI_API_KEY` | 필수 | Gemini 무료 API 키 |
| `GEMINI_MODEL` | 선택 | 기본값 `gemini-2.0-flash` |

## 최근 변경 이력

- **v1.6**: 저녁 발행 판정 로직을 아침과 동일한 "시간대 범위 진입 즉시 발행" 방식으로 통일.
  아침 코너를 "밤사이 AI 소식"(사건 중심 검색어 + 공감형 후킹→설명→중요성→따뜻한 마무리)으로 개편.
  저녁 코너를 노션 "저녁 소재 노트" 기반 반자동 구조("AI로 이렇게 바뀌었어요")로 전환하고,
  미사용 메모가 없을 때만 기존 뉴스 기반 방식으로 대체 발행하도록 폴백 추가.

## 문제가 생기면

[Actions] 탭에서 실패한 실행의 로그를 복사해 이 문서 + `docs/04_기능_목록.md`와 함께 AI에게 보여주면
빠르게 원인을 파악시킬 수 있습니다. Gemini 404/429 오류, Threads 컨테이너 생성 실패, 노션 DB 조회 실패는
각 함수의 `RuntimeError` 메시지에 원인 점검 힌트가 포함되어 있습니다.
