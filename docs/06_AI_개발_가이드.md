# ⑥ AI 개발 가이드

이 문서는 Claude 같은 AI에게 이 저장소의 문제 해결이나 기능 추가를 맡길 때,
`docs/04_기능_목록.md`와 함께 보여주면 맥락을 빠르게 파악시킬 수 있도록 정리한 문서입니다.

## 계정 컨셉

- 계정: "소담쌤의 AI 쉬운가이드" (@sodam_ai_lab)
- 타겟: 4050세대 (AI가 낯선 직장인·소상공인·부업 준비생)
- 페르소나: `auto_post.PERSONA` 문자열 그대로가 모든 글의 기준 — "따뜻하고, 담백하고, 과하지 않게", 옆에서 알려주는 다정한 선생님 톤, 전문용어 금지, 질문형 마무리 지양
- 브랜드 컬러: `card_news.py`의 `BRAND` 딕셔너리(그린 #255E32, 서브그린 #5B9A42, 골드 #D4B26F, 아이보리 #F8F9F6) — `trend-blog-factory/sodam_image.py`(다른 프로젝트)에 정리된 소담 공식 팔레트와 동일

## 파일 구성

| 파일 | 역할 |
|---|---|
| `comment_bot.py` | 댓글 감시 → 노션 자료 매칭 → 자동 대댓글 (10분 주기) |
| `auto_post.py` | 매일 자동 글 발행 (하루 1회) — 혜택/프롬프트(OPEN·LEAD)/업무활용법/브리핑 카드뉴스 |
| `card_news.py` | 브리핑 코너용 1080×1080 카드 이미지 생성 (소담 브랜드 가이드 기반, Noto Sans KR 가변폰트 내장) |
| `prompt_queue.py` | PROMPT_BANK를 OPEN/LEAD 큐로 나누고 순서대로 뽑는 로직, 글감 목록 문서 생성 |
| `cta.py` | OPEN/LEAD 마무리 문구(팔로우 유도/신청 유도) 로테이션 |
| `post_thread.py` | 수동 글 발행 스크립트 |
| `refresh_token.py` | 이미 살아있는 장기 토큰을 다시 60일로 연장 (완전히 새 토큰이 필요하면 Meta 앱의 "사용자 토큰 생성기" 사용) |
| `threads_api.py` | Threads 공식 API 래퍼 (텍스트/이미지 컨테이너 생성 → 대기 → 발행) |
| `notion_api.py` | 노션 API 래퍼 (자료 DB 전용 — 댓글 자동응답, LEAD 키워드 확인, 신청 CTA 노출 여부 판단) |
| `config.py` | 환경변수 로더 (GitHub Secrets → os.environ) |
| `.github/workflows/*.yml` | GitHub Actions 워크플로 (댓글봇, 수동발행, 자동발행, DB 링크 점검) |

## 자동 발행 흐름 (`auto_post.py`, `main()`)

1. GitHub Actions가 아침 7~9시대/저녁 18~20시대 동안 20분마다 실행 (`current_window()`로 판정)
2. `should_post_now()`로 오늘 아직 발행 안 했는지 확인 — **날짜 기준 하루 1회**, 1순위/2순위 구분 없음
3. `POST_TYPE` 환경변수가 `open`/`lead`/`briefing`이면 혜택·순환큐 판단을 건너뛰고 그 타입으로 곧장 발행 (테스트용)
4. 평소에는 매 실행마다 **정부·지자체 AI 지원 혜택** 소재를 먼저 검사 (`pick_benefit_item`) — 신선도 3점 이상 + 신청 방법 정보 확인 + 환각 검증 통과해야 그 날은 혜택 글로 발행
5. 혜택 소재가 없으면 `POST_CYCLE`(7일 순환 큐: 프롬프트 5 · 브리핑 1 · 업무활용법 1)에서 오늘 자리를 확인
   - `prompt` → `write_queued_prompt_post()` — 요일별 OPEN/LEAD 판정(`determine_prompt_type`) 후 큐에서 글감을 뽑아 작성. **LEAD_ENABLED=False**라 `_active_lead_keywords()`가 항상 빈 집합을 반환 → 사실상 항상 OPEN으로 나감
   - `briefing` → `run_briefing()` — 소재 선정(`pick_briefing_item`, 4일 이내·교차확인 2건 이상·정책 신호어 점수제) → 초안 생성+환각 검증 2단계(`write_briefing_post`) → 카드 이미지 생성(`card_news.generate_card`) → 저장소에 즉시 커밋·푸시해 공개 URL 확보(`_publish_card_image`) → 실패하면 `write_howto_post()`로 대체
   - `howto` → `write_howto_post()` — 노션 자료와 무관, 자체 글감 은행에서 순환
6. Gemini 무료 API로 글 작성 → 줄바꿈/분량 후처리(`wrap_lines`, `trim_paragraphs`) → `threads_api.publish_text`(일반 글) 또는 `publish_image`(브리핑) 로 발행
7. 발행 기록을 `state/posted.json`(하루 1회 판정용) + `data/posted_log.csv`(효과 측정용)에 저장, `docs/글감_발행목록.md` 갱신

## LEAD를 껐다 켜는 법

`LEAD_ENABLED`(auto_post.py 상단, WEEKDAY_TYPE_MAP 바로 아래)가 `False`면 노션에 자료가 등록·게시되어 있어도 전부 무시하고 OPEN으로만 발행합니다. 노션 자료를 다시 꾸준히 채울 수 있을 때 `True`로 바꾸면 `WEEKDAY_TYPE_MAP`(수·토·일 LEAD)이 그대로 되살아납니다. 관련 테스트는 `tests/test_open_lead.py`의 `test_lead_disabled_by_default_ignores_registered_keywords`(기본 꺼짐 확인)와 `LEAD_ENABLED=True`를 명시하는 두 테스트(활성화 시 동작 확인)를 참고하세요.

## 노션 DB 구조

### 자료 DB (`NOTION_DATABASE_ID`) — 댓글 자동응답 + LEAD 큐 판정용

| 속성 | 타입 | 설명 |
|---|---|---|
| 제목 (title) | 제목 | 자료 이름 |
| 키워드 (`NOTION_KEYWORD_PROP`, 기본 "키워드") | 텍스트/선택 | 댓글에 이 키워드가 있으면 이 자료 링크를 보냄. 쉼표로 여러 개 가능 |

- "공유 > 게시(Publish)"를 켠 페이지만 `public_url`이 내려와 대댓글 전송 대상이 되고, LEAD_ENABLED=True일 때 LEAD 큐 자격도 이 조건(`get_lead_ready_keywords`)을 씁니다.
- `NOTION_HUB_TITLE`(기본 "AI 프롬프트 5종 모음")과 이름이 같은 페이지가 있으면, 구체 키워드 없이 `DEFAULT_KEYWORD`(기본 "신청")만 댓글에 있을 때 이 페이지가 대신 나갑니다. `notion_api.has_any_material()`이 이 허브 페이지의 존재 여부로 "신청 유도" 마무리 문구 노출 여부(`auto_post.pick_closing_line`)를 결정합니다.

## 카드뉴스 이미지가 공개되는 방식 (`_publish_card_image`)

Threads의 IMAGE 컨테이너 API는 로컬 파일이 아니라 공개 URL이 필요합니다. 별도 이미지 호스팅 없이, 생성한 PNG를 `cards/` 폴더에 저장 → `git add/commit/push`로 저장소(main 브랜치)에 즉시 반영 → `raw.githubusercontent.com/{owner}/{repo}/{branch}/cards/...` URL을 Threads에 전달하는 방식입니다. 푸시 직후 CDN 반영 대기로 8초 sleep을 둡니다. 이 커밋은 워크플로 마지막의 "발행 기록 저장" 스텝과 별개로, 발행 API를 부르기 전에 먼저 끝나야 합니다.

## 문제가 생기면

[Actions] 탭에서 실패한 실행의 로그를 복사해 이 문서 + `docs/04_기능_목록.md`와 함께 AI에게 보여주면 빠르게 원인을 파악시킬 수 있습니다.

- Gemini 404/429, Threads 컨테이너 생성 실패, 노션 DB 조회 실패는 각 함수의 `RuntimeError` 메시지에 원인 점검 힌트가 포함되어 있습니다.
- `OAuthException`/`"API access blocked"`(code 200)는 토큰이 아니라 **Meta 앱 쪽 권한·역할 문제**일 수 있습니다. `developers.facebook.com` → 내 앱 → Threads API → 설정에서 테스터 등록 상태(`@sodam_ai_lab`이 남아있는지)와 권한별 상태("테스트 준비 완료" 인지)를 확인하세요. 새 토큰은 같은 화면의 "사용자 토큰 생성기"에서 바로 발급되는 값을 별도 교환 없이 그대로 쓰면 됩니다.
- 워크플로가 "성공"인데 실제로는 아무것도 안 올라갔다면, 그 시각이 발행 시간대(7~9시/18~20시 KST) 밖이었을 가능성이 큽니다 — `state/posted.json`에 오늘 날짜 키가 생겼는지로 실제 발행 여부를 확인하세요.

## 최근 변경 이력

- **v2.x (2026-09)**: AI 브리핑 카드뉴스 코너 추가(주 1회, `card_news.py`). 브리핑 소재 검증 강화(발행 시각 불명 기사 제외, 최소 2건 교차확인, 정책 신호어 점수제, 기사 발행일을 코드에서 직접 계산해 캡션에 첨부). 노션 소재 부족으로 LEAD(신청 유도) 발행을 `LEAD_ENABLED=False`로 일시 중단, 전부 OPEN으로 대체. "저녁 소재 노트" DB 기반 반자동 저녁 발행(구 v1.6 방식)은 더 이상 쓰지 않음 — 현재는 혜택/프롬프트(OPEN·LEAD)/업무활용법/브리핑 4종을 하루 1회 순환.
